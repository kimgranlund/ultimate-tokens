# Anchors a palette did not get: pre-v5 kits and hueless samples (#740, #744)

Two gaps left by #681's stored anchors, both about what a palette carries when it was never sampled through the new path.

The first (#740) is persistence. A kit saved before schema v5 (persist.js `CURRENT_SCHEMA_VERSION` was `4` at 7d20c42d, the commit before #681 landed) has no `anchor` on any palette, and `hydrate()` keeps absence absent by design, so the kit renders through the non-anchored path with no notice. The critic on PR #737 measured it on the one document every user has: a saved, unedited default kit renders `16/16` ramps differently from a fresh default. Measured again here at 7d325b32 by stripping `anchor`/`sourceAnchor` and `schemaVersion` from a serialized `defaultDocument()`: `16 of 16` ramps differ. The fix is a provenance backfill in `hydrateStoredDoc` (the seam that already stamps `hueSpace: "cam16"` on a pre-`hueSpace` stored doc): a palette in a pre-v5 stored doc that still equals a default-kit row on name, hue, chroma, skew and lift regains that row's `anchor` and `sourceAnchor`. Measured with that rule at 7d325b32: `0 of 16` ramps differ, `16` anchors stamped, a row whose hue was edited by one degree is left alone (`15` stamped), and a v6 doc without anchors is untouched (`0`). Everything else in a pre-v5 doc stays parametric, on purpose and documented: a user-built palette has no source colour to anchor to (the New-Palette modal stores none even today), and a stored curated preset cannot be matched to today's corpus because #681's regeneration changed `lift` on `3363` of `3780` palettes (only `417` rows and `5` presets are equal on all four numbers), so a backfill there would pin today's anchor onto yesterday's fitted shape. Q1 puts the wider options to the owner.

The second (#744) is the generator. `scripts/gen-categories.mjs`'s `palette()` stores `Math.round(oklch[2])` as a sample's hue, and a hueless sample (`"oklch": "1.000 0 0"`, the only one in the corpus: Nike "Box white", `#FFFFFF`) stores hue `0`. Since #739 an achromatic anchor renders its ramp at the palette's stored hue, so that palette renders a mauve ramp at hue 0 (`650:#B8969F`, max CAM16 C `33.21`). The fix is one rule in the generator: a hueless sample takes the entry's derived neutral hue, `Math.round(deriveNeutral(swatches)[2])`, the same chroma-weighted circular mean `deriveNeutralPalette` already uses for the entry's neutral, `36` for Nike. Measured at 7d325b32 with the generated file patched to hue 36: `650:#B8988F`, max CAM16 C `27.28`, stop 650 CAM16 hue `35`, the four sampled colour gates green, and the full tonal gate red on exactly the re-freeze the design names (one new `KNOWN_BASELINE_DUP` key at hue 36, the two hue-0 keys gone).

## The design, stated once

U1 (#740). In `src/ui/model.mjs` the `DEFAULT_PALETTES` declaration gains `export` (one word, no other change; `defaultDocument()` stays the app's source). In `src/ui/app-helpers.mjs` a pure exported function `backfillDefaultAnchors(stored)` returns the same object when `stored.schemaVersion` is a finite number at or above `5`; otherwise a copy in which every palette that has no `anchor` and equals, on `name`, `hue`, `chroma`, `skew` and `lift`, either a `defaultDocument().palettes` row (the OKLCH-hue form every doc since `hueSpace` stores) or a raw `DEFAULT_PALETTES` row (the pre-`hueSpace` form) gets that row's `anchor` as both `anchor` and `sourceAnchor`. Equality is `===` on the four numbers: `serialize`/`hydrate` keep an in-domain float byte for byte, so an unedited row matches exactly and a slider edit (integer steps) does not. `hydrateStoredDoc` calls it after the `hueSpace` stamp and before `hydrate`, so the stamp keeps its own contract and `hydrate`'s allowlist clamps the stamped hexes like any other (`clampHex`, uppercase). No `RENAME_MAPS` entry: the persist layer cannot see the default kit, and the stamp is about provenance, not a rename; the comment above `RENAME_MAPS` in `persist.js` is not edited (docs-repair's file), the new function's own comment says why it lives here.

The gate, one block in `test/ui/persist.mjs`, id `stored-anchors`, importing `hydrateStoredDoc` and `backfillDefaultAnchors` from `app-helpers.mjs` and `defaultDocument`, `projectView` from `model.mjs`: (a) a serialized default doc with `schemaVersion`, `anchor` and `sourceAnchor` stripped renders through `hydrateStoredDoc` byte-identical to the fresh default on every ramp and carries 16 anchors; (b) the same with Primary's hue moved by one carries 15, Primary excluded; (c) the same stamped `schemaVersion: 6` carries none; (d) the raw-row legacy form (the 16 `DEFAULT_PALETTES` rows minus `anchor`, `hueSpace` absent) carries 16 after `hydrateStoredDoc`; (e) the existing identity fixture still hydrates with no anchor. On the old code (a) and (d) red.
