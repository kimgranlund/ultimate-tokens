# ADR-012 · Ramp hue anchored in each path's RENDER space (per-path direct solve) · 2026-07-12 · DECIDED
| Field | Value |
|---|---|
| Decision | Anchor the hue in the space each ramp renders, at the KEY stop (500)'s actual chroma + lightness, not a peak-tone proxy. Each path Newton-solves its own author-space hue so stop 500 reads back at the set OKLCH hue: perceptual/peak via `solveOkhslHue(targetOklchHue, s₅₀₀, l₅₀₀)` (shipped #201/#202), even via `solveCam16Hue(targetOklchHue, c₅₀₀, tone₅₀₀)` over `hctToOklch`. `effHue`/`hueAnchorFrac` are retained for the `hueSpace:"cam16"` passthrough, the even path's gamut basis, and the OKHSL cusp seed. |
| Forces | ramps are exported in OKLCH but authored in OKHSL (`okhslStops`) or HCT/CAM16 (`paletteStops`), "constant hue" disagrees between author space and OKLCH by a chroma- and lightness-dependent amount (Abney effect), a single peak-tone anchor left stop 500 off by ~6° on perceptual blues and up to ~9° on the even path under `dampAmp`, same discipline as ADR-011 |
| Rejected | none named |
| Consequences | A few extra Newton iterations per palette (loop ≤16 steps, converges in ~3). `role-table.json` is UNCHANGED (render-layer calibration, not a role remap). Only OKLCH-hue palettes shift; `hueSpace:"cam16"` docs render byte-identical. Result ~0.5° across the wheel, any damping, both paths (from 6°/9°). Gate `oklch-hue-anchor` in `test/engine/tonal.mjs` asserts stop 500 exports within 1° of the set hue across the wheel incl. blues, both ramp paths, at `dampAmp` 0 and 66. |
| Supersedes / amended by | Complements ADR-011; none stated as superseded |
