## The defect, mechanism first

`resolveAnchor` (`tonal.js:551`) reads the anchor's hue twice: `rgbToOkhsl(rgb).h` for the OKHSL branch (perceptual and peak, `okhslStopsAnchored`, `hOkSeed = anchor.okhsl.h` at `:985`) and `cam16FromRgb(rgb).hue` for the CIE path (even, `paletteStopsAnchored`, `seedHue = anchor.cam.hue` at `:713`). Both are `atan2` of OKLab or CAM16 `a`, `b`. For a grey, `a` and `b` are rounding residue, and the angle is whatever the residue points at: OKHSL `h` 89.88 for every `r = g = b` grey (the `#808080` case in the issue), CAM16 hue 209.49 for the same greys, and for `#000000` both read 0, which the U10 guard preserved when it set `s = 0` (`okhsl.js:194`). The anchored construction then holds that hue constant across the ramp while `anchorChromaBasis` blends the anchor's own near-zero chroma at stop 500 toward the group's resolved ramp target at the ends (REQ-002, `knowledge-02` §9 "Chroma at the pivot is a blend"), so the ends get real chroma at a hue nobody chose. The palette's stored `hue` (the field the non-anchored path renders from through `effHue`, `tonal.js:1060`) is never read on either anchored branch.

A second, separate reading error compounds the white case. `rgbToOkhsl([255, 255, 255])` returns `s = 0.5583` (`#FEFEFE` returns `1.6e-5`): at `L = 1` the gamut bounds `getCs` returns are zero width, and the `C / (k1 + k2 * C)` formula divides one rounding residue by another. U10 guarded `L <= 0` only. On the window-clamped white pivot (`okhslStopsAnchored`'s `pivotL` solves at `anchor.okhsl.s`, `:1009`), that bogus saturation is what the clamped stop 500 renders at, which is why Nike "Box white" renders `500:#F8F1DE` and climbs to C31.5 at 650 from a group whose ramp chroma is the only chroma the ramp should reach for.

The prime ladder is not affected: `primeSwatches` holds chroma at the anchor's own CAM16 chroma (`prime.mjs:121` to 135), so the seven rungs of a grey anchor stay grey (measured below). This plan leaves `prime.mjs` alone and proves it stays byte-identical (U1-7).

## The design, stated once

One named constant in `src/engine/tonal.js`, `ACHROMATIC_ANCHOR_C` (OKLab chroma, recommended `0.002`, Q2), and one rule in `resolveAnchor` or beside its two callers: an anchor whose OKLab chroma is below the constant is achromatic, and an achromatic anchor contributes lightness and its own (near-zero) chroma at the pivot but no hue. On the OKHSL branch the hue seed becomes the palette's stored hue (OKHSL hue is the OKLab hue, so `palette.hue` is used directly, the way `okhslStops`'s non-anchored path takes `baseHue` from `effHue(palette.hue, ...)` at `:1060`), plus `hueShift` exactly as today. On the CIE path (even) the seed becomes `effHue(palette.hue, controls.hueSpace, hueAnchorFrac(palette, controls))`, the non-anchored path's own seed, so `hueSpace` keeps the meaning Q-D gave it there. Every other line of both branches is untouched: `anchorLerp`, `anchorChromaBasis`, `chromaEnvelope`, the window clamp, the `stop === 500 && !clamped` verbatim case, `enforceMonotonePixelL`. A chromatic anchor (C at or above the constant) renders byte-identically to today; U1-4 proves it over the corpus.

`rgbToOkhsl` gets the mirror of U10's black guard: at `L >= 1` (white), `s = 0`, `l = 1`. `#FEFEFE` and every other colour are untouched (U1-2's second line).

Under Q1 (b) instead, the achromatic anchor also pins the basis: `anchorChromaBasis`'s group target is 0 for an achromatic anchor, so the ramp stays neutral end to end and REQ-002 goes inert for it. The plan is written for (a); (b) changes U1-1's Expected and U1-3's bound only, recorded as a revision if the owner picks it.

Why (a) is recommended. It is what the engine already does for a near-grey anchor (Nike secondary-muted above), it keeps REQ-002 live (a user can tint a grey-anchored ramp from the group's Base chroma without detaching the anchor), it matches the corpus (every fitted anchor stores its own hue), and a grey anchor in a chroma-3 group renders neutral anyway because the group target is what the ends reach for. (b) makes Base chroma a dead control for one class of palette, which is the F4 class the pre-land review named.

import { pathToFileURL } from "node:url";
const u = (p) => pathToFileURL(`${process.cwd()}/${p}`).href;

const h = (s) => Math.round(cam16FromRgb(s.rgb).hue);
for (const toneMode of ["perceptual", "peak", "even"]) {
  const c = { ...DEFAULT_CONTROLS, toneMode };
  const a = paletteStops({ hue, chroma, skew: 0, lift: 0, anchor }, c, STOPS);
  const r = paletteStops({ hue, chroma, skew: 0, lift: 0 }, c, STOPS);

  const d = (n) => Math.abs(((h(at(a, n)) - h(at(r, n)) + 540) % 360) - 180);

}
