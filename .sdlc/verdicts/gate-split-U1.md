## Advisory judged: does `docKey` collide?

`docKey` is `` `${doc.category}/${doc.name}` ``. It cannot collide today, and needs no row.

Measured on the unit head: `0` of the 8 category names contain a slash, `343` curated documents yield `343` distinct `docKey` values. Because no category name carries a slash, the first slash in a key always separates category from name, so the join is injective over the real corpus however exotic a document name gets. `5` document names do carry a slash (for example `Bankside / Tate Modern · 1947, conv. 2000 · London`), which is exactly the case a naive join would be blamed for, and it is harmless for that reason. Category names come from the basenames of `src/ui/categories/*.js`, which no filesystem lets carry a slash, so the injectivity is structural rather than lucky. One nuance, not a defect: the throw message hard-codes `category "X" holds two documents named "Y"`, which would read wrong for a cross-category collision, but that collision needs a slash in a category name and so cannot be reached.
