# ADR-015 · The product is unattributed: no maker brand, no "by" line, no monogram · 2026-07-12 · DECIDED
| Field | Value |
|---|---|
| Decision | Retire the maker brand entirely. The product is "Ultimate Tokens" in every mention, no longer form, no attribution; copy speaks as "we" and nothing signs the work. |
| Forces | the product shipped as "Ultimate Tokens by <the maker brand>" with an "N" monogram and a a maker-domain support/docs/account surface, every replacement link must resolve today rather than ship 404s behind a domain nobody owns, a find-and-replace decays because re-attribution by muscle memory is a factual claim about who makes this, "a workshop that names itself is performing smallness; one that ships is demonstrating it" |
| Rejected | none named |
| Consequences | Support is GitHub Issues, docs are the repo README, billing is Lemon Squeezy's own customer portal; unbuilt hosted-MCP and magic-link URLs became `<APP_DOMAIN>` / `<MCP_DOMAIN>` placeholders so Phase B must acquire a domain as step zero. The "no nouns, just verbs" stance stays, only its origin story went. The monogram and its eight `ico-<maker>-*` assets were deleted and the favicon set regenerated from four tonal swatches. `test/repo/branding.mjs` runs in `npm test` and fails on the maker-brand word, any maker-domain URL, and the pre-rename identifier outside a named back-compat allowlist; `voice-check.mjs` raises the word to ERROR in copy. Only the `migrateStorageKeys()` prefix chain still names the old identifier (data compatibility, see ADR-014); the pre-rename element tag went with the brand; a new file may not quietly join the allowlist. |
| Supersedes / amended by | Drives the 2026-07-09 (#250) amendment of ADR-014; none stated as superseded |
