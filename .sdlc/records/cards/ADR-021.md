# ADR-021 · The hosted describe-palette MCP breaches "the generator stays client-side"; the server-side interpreter is demoted to a non-agent-only path · 2026-07-18 · DECIDED
| Field | Value |
|---|---|
| Decision | The "generator stays client-side" constraint in `docs/site/mcp-hosting-spec.md` §1 is amended narrowly: server-side generation is permitted only for the describe-palette surface (`generate_kit` + `describe_palette` on the Phase B Worker, #377), gated server-side via `flagOf("describePalette")` entitlement, never a client-side check; every other surface (app SPA static, Figma plugin offline, downloadable/local flavor, hosted kit-sync) keeps the original constraint verbatim. Within that surface, the server-side LLM `describe_palette` exists only for LLM-less clients (the web describe box, plain HTTP/curl); agent callers are steered by tool descriptions alone to the self-teaching `generate_kit{description}` → `generate_kit{brief}` two-step (#371), where the caller's own model interprets. `describe_palette` calls its provider with forced tool-use against the `PaletteBrief` schema and echoes the brief back in `meta.brief`; local and hosted `generate_kit` surfaces stay parity-gated identical (G1–G3, spec §8), with `describe_palette`'s hosted-only existence plus `list_kits`/`kit` the only permitted asymmetries. |
| Forces | Pro tier anchor needs an entitlement-gated recurring-value capability (`describePalette` ruled Pro-gated 2026-07-18, #379), an LLM-less client has no other way to interpret a description into a brief, routing an Opus-class agent through a Haiku-class server interpretation would cap quality and add per-call provider cost, an open server-side LLM surface is an abuse vector (cost-drain, prompt-injection-via-description), the local flavor's "No server-side LLM" design (spec §1), a server-side LLM call is a new distinct capability rather than "the same engine hosted" |
| Rejected | Keeping the constraint intact ("never ship the described-value Pro feature"); exposing the server-side interpreter to every caller equally as a second front door |
| Consequences | `docs/site/mcp-hosting-spec.md` §1 updated to reference this ADR at the constraint line, with "the generator stays client-side" remaining the default/general rule and this ADR the named exception; `describe-palette-spec.md` §1/§8 already cited it and needed no change; `mcp/describe-mcp-core.mjs`'s local `generate_kit` is unaffected; no code to retrofit today since #377's hosted build has not started (blocked on domains and Phase B accounts); when #377 is built, `describe_palette`'s own tool description must state the LLM-less-only intent in-band. Ratified via issue #376; unblocks nothing by itself but removes §13's open ratification question ahead of #377. Issues named: #369–#374, #371, #376, #377, #379. |
| Supersedes / amended by | none stated (this ADR amends the constraint in `docs/site/mcp-hosting-spec.md` §1) |
