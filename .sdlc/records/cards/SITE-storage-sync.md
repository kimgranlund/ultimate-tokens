# SITE-storage-sync · SPEC — Storage & Offline-First Sync · 2026-07-12 · draft / design (for later)
| Field | Value |
|---|---|
| Decision | A local-first durable store is the source of truth and the UI never waits on the network; every change appends an idempotency-keyed mutation to a durable outbox drained by a background sync worker (Service Worker when available, foreground reconciler otherwise), web-only and never in the Figma plugin. Owner reference is an unguessable anonymous device id (≥128 bits) until sign-in, then an account id; anonymous data is claimed into the account on first sign-in idempotently with zero loss, claimable by at most one account (`409 already_claimed`). Anonymous docs stay local-only until a first sync trigger (export, hosted-MCP use, or sign-in), after which replication is sticky (SPEC-R2/R2a). Conflicts resolve by last-writer-wins on `(version, updatedAt, ownerRef)` with the losing body preserved as a conflict copy (SPEC-R15); pull never clobbers un-synced local mutations (SPEC-R16). Deletion is a syncing tombstone; unclaimed anonymous server data is hard-deleted after 90 days from last activity (SPEC-R18/N5); owner isolation returns `404` cross-owner (SPEC-R20). Server is Cloudflare (D1 metadata + mutation ledger, KV/R2 blobs) reusing the accounts/auth from `mcp-hosting-spec.md`; typed contracts in §5 (`OwnerRef`, `DocEnvelope` with client-minted UUID `id`, `Mutation`, `POST /sync/push`, `POST /sync/pull`, `POST /account/claim`, `DELETE /docs/:id`, `DELETE /account`). |
| Forces | PRD-G1 never lose work (including free/anonymous users), PRD-G2 offline-first with sync off the UI critical path, PRD-G3 anonymous → account → Pro/Studio with zero data loss, PRD-G4 multi-device and Studio team continuity, PRD-G5 synced kits feed the hosted MCP, PRD-G6 safe/private/low-cost with the Figma plugin offline, NFR targets (local action < 50 ms p95, server convergence ≤ 5 s, doc body ≤ 256 KB, push batch ≤ 100 mutations / ≤ 1 MB, deletion SLA ≤ 24 h, no main-thread long task > 50 ms) |
| Rejected | Real-time multi-user co-editing / CRDT merge (v1 non-goal, LWW only); rich version history/branching beyond a single conflict copy; syncing app preferences in v1 |
| Consequences | The synced `brand-kit` body is the payload the hosted MCP serves (one storage layer, two readers); owner-reference authentication reuses the magic-link account + session from `mcp-hosting-spec.md` §4–5; all sync code is a web-only seam in `src/main.ts` absent from the plugin bundle (SPEC-R14). Open items for LLD (§8): local engine (IndexedDB vs OPFS), blob store (KV vs R2 vs D1-blob), the per-device anonymous cap, background mechanism choice, conflict model beyond LWW. Decided and folded in: local-only until first sync trigger then sticky; 90-day anonymous retention. Composes under `docs/site/mcp-hosting-spec.md`; rubric spec-author gate dims S1·S2·S4·S7. No tickets or issues named. |
