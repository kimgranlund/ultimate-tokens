# New verdict records carry a machine-readable `verdict:` line, and a check refuses one that does not

#723 says a record under `.sdlc/` can assert a fact about other work that nothing re-derives, and names the prerequisite: one machine-readable source of a verdict's state. At f685529f, 44 of 68 verdict files carry no `verdict:` line and three more carry one whose value is prose (`FIX-FIRST` twice, `green-with-one-note` once), so a script reading state has nothing to read. The owner ruled: mandate the field on new files, backfill later. This plan lands the mandate, the check that enforces it, and a grandfather list holding exactly the files that fail at the pinned sha, so the check exits 0 on the head and exits 1 on the first new file that skips the field. The backfill is U2's ticket, not this plan's work.

Which line is the state. The adapter already answers this: `read_gate` overwrites the field on every match, so the LAST `verdict:` line in the file is what `adapter.py land --gate` reads, and the multi-pass pre-land shape that landed at 74c02a39 puts one `verdict:` under each `## Pass N` block, the latest pass last. The mandate follows both: the state is the last line starting `verdict:`, and its first token is 🟢, 🟡 or 🔴. A record re-graded in a later pass appends a new block with its own line, and the check and the adapter read the same one. Revision 1 read the first line and forbade a line below a heading; that contradicted the adapter (a 🔴 head with a 🟢 re-grade would have passed the check and been refused by the gate, and the reverse would have passed the gate) and redded every multi-pass record, so it is gone.

Scope wall. Paths this plan may change: `.sdlc/checks/verdict-frontmatter-check.sh` (new), `.sdlc/checks/verdict-frontmatter-grandfather.txt` (new), `.sdlc/adapter.md` (one amendment paragraph under §6 and one new line appended inside §2.1 after item 1; no existing line changes), this plan, its handoffs, verdicts and questions, and the board's own rows. No file under `.sdlc/verdicts/` is edited, added or removed by a builder: the verdict files this plan's own seats write are new files and carry the field. Nothing under `src/`, `test/`, `scripts/`, `.github/`, `package.json`: wiring the check into `npm test` is Q1, and `test/run.mjs` is under contention from #713 U1 and `plan/rule-gates`.

Prose rules for every line this plan adds. No em dash (U+2014) outside an inline backtick span that quotes program output. No bold inline labels. The retired maker brand is paraphrased, never quoted. `grep -P` is absent on this host: PCRE runs through `perl`. The shell is zsh, where `${PIPESTATUS[0]}` is empty: a command that needs a pipe's exit code runs under `bash -c`.

Diff bases. A P row diffs against `$(git merge-base origin/main HEAD)`, which on the plan branch is the commit the plan was cut from, so a pre-land rerun sees every landed unit. A unit row diffs against the plan tip, `$(git merge-base plan/verdict-frontmatter HEAD)`, in the unit worktree only; at pre-land the verifier reruns it with the P-row base.
