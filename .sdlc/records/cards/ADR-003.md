# ADR-003 · On-colors fixed to `050` in both modes · 2026-07-12 · DECIDED (OVERRIDE)
| Field | Value |
|---|---|
| Decision | `on{N}` → `050` (both modes), `on{N}Variant` → `200` (both modes), for all palettes. The previously implemented contrast-aware auto-pick logic was removed. |
| Forces | Explicit user/brand requirement that on-colors be the light tint uniformly, the user was shown the contrast data and chose this deliberately, "perceptually even" governs ramp spacing not contrast |
| Rejected | Contrast-optimized per-fill per-mode white/black pick (the removed auto-pick logic) |
| Consequences | White-on-`Warning` (yellow) ≈ 1.8:1, below WCAG 4.5:1; in dark mode several palettes lose contrast as fills lighten. Accepted by design. Tracked as OD-001. OVERRIDE flag: do not reintroduce contrast-aware on-colors as the DEFAULT without explicit instruction. Opt-in added 2026-06-25 (explicit instruction): default stays `fixed`; a new `onColorMode` control adds an opt-in `"contrast"` mode that re-points `on{N}` (050↔950) and `on{N}Variant` (200↔800) to the end with better WCAG contrast vs the accent fill (550 light / 450 dark), per mode. It is a resolution-layer adjustment (`applyOnColorContrast`, applied in `projectView` + `derivePalette`); `semanticRoles` and the canonical role table are UNCHANGED. Satisfies OD-001 without overriding the default. |
