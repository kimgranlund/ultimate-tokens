# ADR-014 · The `ultimate-tokens` rename orphans all Figma `pluginData` (no migration is possible) · 2026-07-12 · DECIDED (consequences amended)
| Field | Value |
|---|---|
| Decision | Rename the Figma plugin `id` anyway, accepting that every key it ever wrote is orphaned. `load-config` must degrade to a clean empty config when only pre-rename keys are present (never throw, never silently adopt a stale one; `test/figma/plugin.mjs` `config` gate). |
| Forces | `figma.root.setPluginData` is namespaced by the calling plugin's id with no cross-id read API so pre-rename keys are unreachable from any code path, a migration would have to run under the old id which is what is being replaced, the config also travels in the exported bundle so nothing is unrecoverable, the web app's localStorage keys ARE migratable (same origin, no namespacing) so the asymmetry is the platform's |
| Rejected | none named |
| Consequences | `LEGACY_CONFIG_KEY` (the `"hct-config"` fallback) is dead code and was removed. The user's cost is re-running apply once on an old `.fig`. `migrateStorageKeys()` chains `hct-palette-state-v1` ← `<pre-rename-id>-color-tokens` (the retired maker-brand key, spelled out only in the allowlisted source) ← `ultimate-tokens`, newest legacy wins, never overwrites a present key. The the pre-rename `<…-color-tokens>` element tag element tag stays registered as a deprecated alias. The Color Tokens Semantic Binder plugin keeps its own id (`color-tokens-semantic-binder`). AMENDED 2026-07-09 (#250): the alias was retired because it keeps the retired brand alive in the DOM, `styles.css` and every generated bundle, which the debrand (ADR-015) forbids; an embed on the old tag now renders nothing; the storage half is untouched because the keys carry a user's saved palettes. |
| Supersedes / amended by | Amended 2026-07-09 (#250) by the alias retirement, driven by ADR-015; none stated as superseded |
