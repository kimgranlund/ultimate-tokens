## Design

### U1: two small legs in `citations.mjs` (#769, #775)

Leg (4) gains a self-guard: after the `FACT_PINS` loop, the file reads its own text (`txt("test/repo/citations.mjs")`), slices from `const FACT_PINS = [` to the first `\n];` after it, and runs `bareLiteralSource(slice)` over it. The predicate matches a `source:` whose value is a number literal in any of these shapes: `source: 53`, `source: () => 15`, `source: async () => 15`, `source: () => { return 15; }`, `source: async () => { return 59 }`, any digits, optional sign and decimal. It does not match a function whose body reads (`Object.keys(...).length`, `/regex/.test(...)`, `await import(...)`). A match is a FAIL naming the pin id on the row (the nearest preceding `id:`). The predicate is unit-tested in place against a fixture array (four positives, the five legitimate body shapes the table uses today) that sits BELOW the `];` that closes `FACT_PINS`, so the scan's own slice never reads the fixture. Docs-repair's archived row U6-4 stays as history; this leg is the rule in code.

Leg (5) stops skipping a `/`-less path. When `path` has no `/` and ends in `.mjs`, `.js`, `.json`, `.html` or `.css`, the leg resolves it by unique basename among tracked files under `src/` (`tracked.filter((f) => f.startsWith("src/") && f.endsWith("/" + path))`). Exactly one match: check it like a full path. Zero: the existing NOFILE-shaped stale. Two or more: a FAIL of its own, `ambiguous basename`, never a skip. A `BARE_EXEMPT` list of `{ sym, reason }` rows carries the three prose false-positives the issue names (`typeTokensX`, `geomTokensX`, `steps`, each a family or a plain English word, not a defined symbol) and is refused without a reason, the `DOCS_EXEMPT` rule. A `/`-less path without a source extension (`` `refSlug` (`scrim-200`) ``) stays prose and is still skipped. `SYMBOL_HOME_FLOOR` rises from 12 to the new checked count minus a margin the builder states (the floor exists to catch a vacuous scan, not to pin the count).

### U2: the count-phrase scan and the sibling reach (#776)

Each count pin (`type voices`, `colour formats`, `roles per palette`, `skill type voices`, `skill colour formats`) gains a `noun` (a regex fragment: `voices`, `colou?r formats|formats`, `roles?`) and, for a skill pin, its reach is the whole skill directory (`.claude/skills/<skill>/**/*.md`, from `git ls-files`), not the one `doc`. For a `docs/` pin the reach stays the one doc. The scan grammar, per line, case-insensitive: a number (digits, or a number word one to ninety-nine using `voice-parity.mjs`'s shape, hyphenated tens included, magnitude words refused loudly) followed by a hyphen or a space, an optional single qualifier from a fixed set (`named`, `colour`, `color`, `semantic`, `export`), and the noun. Every match whose number is not the engine's value fails, naming file, line and phrase, unless the phrase is in the pin's `allow` list, each entry `{ phrase, reason }` and refused without a reason. The allow entries this plan authorises, from P4: `thirteen voices`, `13 voices` (the SM/MD/LG subset), `five voices` (the mono role's share). `two interactive voices` and `one voice` fall outside the grammar (an adjective between number and noun; a singular noun) and need no entry; the plan says so and the builder adds none. The existing needle leg stays: a doc that drops the fact entirely still fails. A `COUNT_PHRASE_FLOOR` (the number of true phrases the scan must have read, measured by the builder at its head and stated in the handoff) reds a vacuous scan the way `SYMBOL_HOME_FLOOR` does.

The three universal-claim comments in `src/engine/type.mjs` (P9's three stale phrases) change to the split one, worded so that none of P9's three needles survives: "thirteen voices carry three steps, SM, MD and LG; UI-control and UI-widget carry six, XS to 2XL" (or equivalent prose that never spells `3-step SM/MD/LG ramp`, `each voice's SM/MD/LG are literal` or `[SM, MD, LG] literal px`). The rewritten lines may still carry the bare string `SM/MD/LG`, so U2-9 counts the three stale phrases, not that string. The four `typography.js` comment sites (P15) change the same way: fifteen voices, 51 steps, the two six-step UI voices named; two of them are trailing comments on a `const cats = Object.keys(...)` line, so the code text of that line is unchanged and only the comment moves (C5 compares comment-stripped sources, not diff lines). Comments only; no code line moves, so the engine's rendered output cannot move, and U2's builder and verifier still run the ramp-identity row (adapter §1) because the unit touches `src/engine/`.

### U3: `renameparity` in `test/figma/binder.mjs` (#772)

A new gate beside `colorparity`/`collparity`/`floatparity`, named `renameparity` and added to `DECLARED`. It extracts each of the three constants from `binderSrc` by a regex on `(const|var|let) NAME = <literal>;` (the flagship declares `var GEOMETRY_FIELD_RENAME_MAP`, the binder `const`; the literal is one line today, the regex accepts a multi-line literal up to the first `;` at line end), evaluates the literal with `new Function`, and deep-compares (`JSON.stringify` after key sort) against `migrations.mjs`: `SEMANTIC_RENAME_FROM` against `FIGMA_MIGRATIONS.color.collections["Color Roles"]`, the two maps against their exports. A constant the regex cannot find is a FAIL (`binder is missing NAME`, the `colorparity` pattern), never a pass. The flagship `figma/plugin/code.js` carries the same two maps outside any generated marker (P10), so the gate reads them there too, from `flagSrc`, the file the two existing parity gates already load; that is one more `for` iteration and closes the lockstep the `migrations.mjs` comment describes. The four lockstep comments (two in `code.js`, two in `migrations.mjs`) gain the clause "and gated by `renameparity`", and `figma/README.md`'s hand-kept paragraph gains one sentence naming the gate, the stale-record rule.

### U4: E1 and E2 bind to the enclosing string (#764)

Two halves. In `classifyLine`, the E1 and E2 legs iterate the line's dash indices and, for each, take `enclosingStringContent(line, idx)`; the leg fires only when a same-line string encloses THAT dash and the string's own content matches (`E1_RE` against the quote plus content, `E2_RE` against the content before and including the dash). The decision carries the matched `idx`. In the fix switch, the `R2s`/`R3s` case uses `decision.idx`, not `masked.indexOf(DASH)`; `R2`/`R3` (the `.md` whole-line shapes) keep the first-dash behaviour, which is correct for them. A line with two strings, a plain one first and a heading string second, then reads: the second string's dash takes the colon (`R2s`), and on the next loop pass the first string's dash falls to `R8` (comma). Two fixtures join the self-test: the issue's two-string line, and P13's template-literal line, where after the fix neither dash has a same-line enclosing string, so both fall to `R8` and the result equals the base tool's (two commas), no longer worse than it. Verdict row F2 (E1 to E3 fire on every non-`.md` line, `.sh`, `.yml`, `.css`, `.txt` included) is Q1 below with a default of keep; U4 changes nothing there.
