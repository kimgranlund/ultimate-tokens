# U7 re-diagnosis: a needle proves the code tests a condition, not that the condition can fail

## 1. Root cause

The false sentence (`README.md:160-161`, `once one exists an All button shows every breakpoint side by side`; `:164-165` by `the same`) is a conditional. The ledger row that covers it (`All button only once a mode exists`, needle `modes.length ? [{ id: "compare", label: "All"`, anchor `typography.js:172`, kind `present`) passed because the anchor line does carry the needle. That is all a `present` row can establish: the code mentions the thing. A sentence of the form "X only when C" makes two claims, that X is gated on C and that C can be false, and the second is decided somewhere else. Here `modes` is `this._typeEffectiveModes()` (`typography.js:163`), which is `typeEffectiveModes(doc)` at `model.mjs:89-93`: when `doc.type.modes` is empty it returns the Standard set, Tablet and Mobile. Measured in the clone: `typeEffectiveModes({})` and `typeEffectiveModes({ type: { modes: [] } })` both print `Tablet,Mobile`; the geometry twin the same. The guard at `:172` never takes its empty branch, so All is on every set, and the sentence's condition never holds.

Where the condition came from. It is not U7's invention:

- `typography.js:171` and `geometry.js:224` carry the comment `Meaningless with only the base, so only when ≥1 mode.` A comment describing a guard that cannot fail. U1's class (a comment read as behaviour), one file over.
- The U1 re-diagnosis anchored C15 and C19 on that guard (`modes.length ?`) and its F4 told the U1 builder to write `compare labeled All when at least one mode exists` into the Geometry row to match Typography's. That sentence is now merged at `ui-plan.md:50` and `:51`. The planner re-derived the sentence from the test site and never opened `typeEffectiveModes`. Stale record: §5 repairs it.
- U2's glossary `Compare` row (`glossary.md:45`) says `offered only when modes exist`, merged.
- U7's step (1) says read Revision B first, so U7 inherited the sentence with its anchor and wrote a README paragraph around it. Its ledger row is a faithful copy of C15.

Why three seats passed it. The builder, the reviewer (`Behaviour sentences: read each against src ... none false`) and the ledger all read `typography.js:172`. Same line, same mechanism, one leg (the independence law in `checks-that-bite`). The verifier found it by asking a different question: what is `modes`, and can it be empty. Nothing in U7's rows asks that. U7-4 is U1-8's row verbatim, a needle-presence check, and R10 makes needles names and counts, so a conditional sentence has no needle that can fail: `modes.length ?` is present whether or not `modes.length` can be zero.

The class, stated once: a `present` row is the right check for "the code has this id, this label, this branch". It is the wrong check for "this happens only when", "unless", "except", "once", because the sentence's truth is decided at the site that produces the value, not the site that tests it. The fix is a second kind of ledger row whose anchor is a probe of the decider, run, with the output compared to a stated needle. §3 has the row; its negative control is F1 itself.

Grade: pass 1 ran builder-l2, reviewer-l1, verifier-l1. The level did not write the false condition (the planner did, at the U1 re-diagnosis); the missing check is procedural and is now a row. Pass 2's grade is the Orchestrator's floor for a pass 2 builder, §6.
