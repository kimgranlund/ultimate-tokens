# The 47 grandfathered verdict records get their `verdict:` line, and the grandfather list retires

#723 made the `verdict:` line mandatory on new records under `.sdlc/verdicts/` and grandfathered the 47 files that failed the rule at `f685529f`, pinned so the list cannot grow. #734 is the backfill: each listed file gets the line, its name leaves the list in the same commit, and the list ends empty. The owner's direction for this plan is to backfill all 47 and to fix the six follow-ups the #723 pre-land carried (N1 to N6). This plan does both, and reads the follow-ups the way they were found: all six are defects of the list and pin mechanism (a pinned name that carries any field-less content, a pin that moves with the script, a file deleted with its name, a re-pin recipe that misses the script's constant, an adapter sentence that names the wrong side as the pin's authority, a grep that cannot go red). Once the list is empty that mechanism guards nothing, so U3 removes it: the check grades every top-level `.md` file, needs no git and no pin, and the six follow-ups close by construction rather than by six patches to code that would then be dead. Q1 puts the alternative (keep the list machinery and patch each N) to the owner.

The token each file gets is the record's own final graded state, not a default. Thirty-one of the 47 state it in their title's first emoji and carry no later block that re-grades it (U1, mechanical). Sixteen state it elsewhere: in a `| Verdict |` cell, a bold `Verdict:` sentence, a `## Pass 2` block that overturns a 🔴 title, or a prose value on an existing `verdict:` line; four of those sixteen are not verdicts at all (an evidence note, a census, a landing authorization, a byte-pinned copy of a review), and Q3 asks the owner to confirm the rule for them. Those sixteen are U2, where the verifier derives every token itself before reading the builder's table, the shape #681's U9-8 uses for its own eleven.

Where the line goes. The adapter reads the LAST `verdict:` line, so the line is placed where it is last and where the record's shape puts state: the last line of the front matter block when the file has one; line 2, directly under the title, when it does not; the end of the file when the final state lives in a later pass block that overturned an earlier one (four files in U2). The three files whose existing `verdict:` line carries prose get a legal token in front of that prose, as #734 says; for the two of those where that line is a superseded pass 1 (`FIX-FIRST`, later `PASS`), the pass 1 token 🔴 goes in front of the prose (FIX-FIRST is 🔴 in this repo's own records, ruled under Q3) and the final 🟢 is appended at the end, so the front matter reads true for its pass and the last line reads true for the record.

Prose rules for every line this plan adds. No em dash outside an inline backtick span that quotes program output. No bold inline labels. The retired maker brand is paraphrased, never quoted. `grep -P` is absent on this host: PCRE runs through `perl`.
