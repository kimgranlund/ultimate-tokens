# ADR-017 · Ticket backend moves from `docs/tickets/*.md` files to GitHub Issues · 2026-07-17 · DECIDED (ratified 2026-07-17; migration execution `TKT-0031`)
| Field | Value |
|---|---|
| Decision | New bugs/features/issues route to GitHub Issues via `gh issue create`, not new `docs/tickets/*.md` files. The payload contract is unchanged (Summary/Acceptance/Links/Scope-Open/Findings as `##` sections); `kind:bug`/`kind:feature` + `size:small`/`size:big` labels replace the frontmatter fields. `docs/tickets/` freezes as the pre-2026-07-17 archive; its 12 done files stay, its 18 open files migrate to Issues (`TKT-0031`). |
| Forces | the file store had grown to 30 files with 18 open and was invisible to GitHub's issue search/labels/assignment/notifications, it duplicated machinery (`status:`, `size:`) Issues provide natively, the repo already ships through GitHub and `gh` is authenticated with `repo` scope, one live backlog beats two because a file-and-Issue split would fork "what's open" with no cross-link, every future `/bug-report`/`/feature` run needs a durable ruling to read |
| Rejected | continuing to accrue file tickets alongside a second store |
| Consequences | CLAUDE.md's Layout section carries the routing-table row scribe's intake Phase 0 reads. Every consumer of the old file contract updates once: `project-docs` (now split pre/post-2026-07-17), any script reading `docs/tickets/*.md` frontmatter (none found at ratification; reverify at TKT-0031), and muscle memory ("check `docs/tickets/`" becomes "check `gh issue list`"). No file-format migration risk: Issues are created fresh from each file's existing text, not parsed mechanically. |
