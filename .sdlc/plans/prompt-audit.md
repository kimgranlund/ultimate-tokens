# Prompt audit: the prompt surface says what the code does, and the counts it states are pinned

An auditor read every prompt file the repo ships or runs on: `.claude/CLAUDE.md`, three repo agents, fourteen repo skills, `docs/reference/SKILL.md`, the consumer plugin (its README and three skills), the MCP tool and instruction text in `mcp/*-core.mjs`, and the one direct API call site (`mcp/describe-eval-runner.mjs` with `describe-rubric.mjs`). Two kinds of finding dominate. Facts that have gone stale against the engine: the consumer typography skill says thirteen voices and its README eleven, the engine has fifteen; the consumer colour skill says on-colours are fixed light by design, the engine's default `onColorMode` is `contrast`; four repo skills point at `src/ui/app.js` for symbols that live in `overlays/drawer.js`, `sections/*.js` and `app-helpers.mjs`; the geometry skill states a caret law and a padding field the code retired. And history narratives, where a ticket or PR number stands in for the rule. The MCP surface has contract gaps of its own: `initialize` names tools a kitless boot does not serve, `resolve_token` never documents its key grammar, `nearest_token` searches ramp stops only and says nothing of it.

This plan applies the High and Medium findings that carry a diff hunk (85 of the 108), in the order the owner ruled: the consumer plugin and the MCP text first, because they ship to users; the repo agents and skills after; the files inside docs-repair's scope wall last, once #751 lands. It adds the gates the owner asked for: every count the audit found stale (voices, per-voice step ranges, the on-colour mode default, the colour format counts, the symbol home files) is pinned to the engine so the next drift reds `npm test`, and every pin ships with a control that proves it goes red when the claim is wrong.

What re-verification changed. The planner re-read the facts behind the High findings at 61225d0c (Measured table below); all of them hold. Three things the audit could not see change the work. First, plan rule-gates (#730) is at its last unit and sweeps the em dash out of 53 of the 55 files in this plan's wall, then gates the glyph at zero: of the 286 context lines the audit's hunks remove, 236 match `origin/main` byte for byte today and only 158 match the swept text, so the hunks are guidance, not patches, and every unit re-derives its edit on the live file (P5 makes the builder record each finding's fate). Second, docs-repair (#751) owns `.claude/CLAUDE.md`, `docs/reference/SKILL.md`, `.claude/skills/building-editor-sections/SKILL.md` and `test/repo/citations.mjs` until it lands; the six findings on those files and the citations-gate pins wait in U8 and U9 (G1). No High or Medium finding duplicates a docs-repair repair; the one overlap is a Low flag (`docs/reference/SKILL.md`'s "five export formats", docs-repair U2), marked dropped. Third, the MCP edits regenerate `src/ui/mcp-assets.js`, `src/ui/describe-mcp-assets.js` and `figma/plugin/ui.html`, so U3 moves the `ui.html` KB figure in `.sdlc/baseline.md` the way okl-memo revision 7 and docs-repair U3 do.
