# `tonal.js` drops the bucketed `_okL` memo (#738)

`src/engine/tonal.js` keeps one module-level memo, `_okL`, in front of `okhslLAt(lstar)`: the key is `lstar.toFixed(2)` and the first caller into a 0.01 L* bucket decides every later caller's value in that bucket. #686 fixed the same class in `hct.js` (`maxChromaInGamut`, `peakC`, `oklchToCam16Hue` now key on the exact float) and ruled that `tonal.js`'s half is this ticket (owner ruling R26 in the #681 pre-land review, finding F5). The fix here is smaller than #686's: the memo is not load-bearing (measured below, under 1 µs per uncached call, two or three calls per palette render), so U1 deletes it instead of re-keying it, and adds a gate that reds on the old code from both directions: the function itself, and a palette render through `paletteStops`.

What the measurement adds to the ticket. On the render path the memo never collides today: `okhslLAt` is called with `controls.lmax`, `controls.lmin` (persisted numbers, default 100 and 5, both values on all 3,780 curated palettes) and `peakC(hue).tone`, which is always an even integer (the `for (let t = 4; t <= 96; t += 2)` search in `hct.js`). A cold-versus-poisoned probe in the shape of `prime.mjs`'s determinism gate (2,000 real palette renders, 1,500 real-palette poison renders first) therefore measures 0/2,000 on the old code and cannot serve as this ticket's tripwire. The collision is reachable through a fractional `lmin` or `lmax` (a hand-authored or imported document; `persist.js` clamps the range, not the decimals), and there it flips hex on every palette: 24/24 palettes at `lmin: 5.25501` shift by one 8-bit step when a cold process evaluated `okhslLAt(5.26499)` first, 0/24 with the memo gone. That is the render-level gate U1 commits, beside the two-value function-level assertion the ticket's own repro gives.

Why delete rather than re-key. An exact key (the #686 shape) keeps a `Map` that grows by one entry per distinct float for the page's lifetime, which is why `hct.js` needed `boundedCache`; `okhslLAt` computes one neutral grey through `hctToRgb(0, 0, L*)` and `rgbToOkhsl`, 0.40 to 0.90 µs uncached on this host, and `paletteStops` calls it three times per unanchored render and twice per anchored one, against a render that costs milliseconds. A corpus-scale render (3,780 palettes, three tone modes, 11,340 `paletteStops` calls) moved by less than the run-to-run drift of the same variant on this host (table below). Nothing to bound, nothing to key: the function becomes the one-line expression the memo wrapped. If the builder's own per-call measurement exceeds the budget in U1-4, it stops and reports rather than reintroducing a cache.

## The design, stated once

In `src/engine/tonal.js` delete the `_okL` line (`:907`, which carries the trailing comment `// L* -> OKHSL lightness (via a neutral gray at that L*); memoized`) and the memo body of `okhslLAt` (`:909` to `:912`, `return v;` included), so the function reads `return rgbToOkhsl(hctToRgb(0, 0, lstar).rgb).l;`. A new comment above the function says the function is pure and why no memo sits here (under 1 µs per call, two or three calls per render, #738), so the next reader does not put one back. `okhslLAtChromatic`, `paletteStops` and every caller stay as they are. Nothing exported changes name or signature.

The gate that outlives the fix, one block in `test/engine/tonal.mjs`, gate id `okl-order`, printing exactly one pass line, `okl-order: okhslLAt is a function of its argument; 0/24 ramps shifted hex by call order`:

1. Function-level, in process: `T.okhslLAt(5.25501)` and `T.okhslLAt(5.26499)` each equal the test's own derivation `rgbToOkhsl(hctToRgb(0, 0, x).rgb).l` (imported from `hct.js` and `okhsl.js`, not from `tonal.js`), and the two differ from each other. On the old code the second call returns the first's value, so the second equality reds whatever order earlier gates called the function in.
2. Render-level, two cold processes through `test/engine/prime-determinism-worker.mjs`, extended with two optional stdin fields: `prelstars` (an array of L* values the worker passes through `okhslLAt` before anything renders) and `ramps` (an array of `{ hue, chroma, skew, lift, hueShift, hueSpace, toneMode, lmin }`, each rendered as `paletteStops(palette, { ...DEFAULT_CONTROLS, toneMode, hueSpace, lmin }, STOPS)` and reduced to its comma-joined hexes). When `ramps` is absent the worker's behaviour and output (a JSON array of `primeSwatches` hexes) are byte-identical to today, so `prime.mjs`'s determinism block does not change. The block sends the 24-palette fixture of the measurement table at `lmin: 5.25501` once with `prelstars: []` and once with `prelstars: [5.26499]`, and requires 0/24 differences.

Both halves red on the old code deterministically (measured: the function-level pair collapses to one value; the render-level pair shifts 24/24), and both are green on the deletion. The render half costs two node spawns plus 48 short renders, about a second, and is why this gate does not need `prime.mjs`'s 2,000-case scale: its poison is a known collision, not a random sweep.

The seven `color-math` lines are rewritten in the same commit: `SKILL.md:91`, `best-practices.md:65` and `rubric.md:15` (C8) say the `hct.js` caches key on the exact float (#686) and `tonal.js` has no memo (#738), and C8's 5-point anchor becomes "a new cache keys on the exact float or does not exist"; `foundations.md:50`, `:53` and `:65` drop their `toFixed` key descriptions for the exact-key wording `hct.js`'s own comments carry; `foundations.md:139` drops `memoized in _okL`. After U1, `grep -c toFixed` over the four files prints `0`.

On the deletion's shape: the memo's comment is a trailing comment on the `_okL` line itself (`:907`), not a line above the function, and `return v;` (`:912`) goes with the body, so the deletion is always five lines (`:907`, `:909` to `:912`) whatever the builder does with the comment (checkability review, U1-7).
