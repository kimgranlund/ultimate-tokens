# ADR-022 · Preset typography declares REGISTERS, not slots; the migration was byte-identical · 2026-07-30 · DECIDED
| Field | Value |
|---|---|
| Decision | `type.slots`/`type.faces` are RETIRED. A spec palette declares `type.registers.{anthemic,contextual,functional,actionable,data}`, slot↔register 1:1 (display→anthemic, heading→contextual, body→functional, ui→actionable, mono→data), each register carrying the same 4 core fields plus optional `styleName` (expressive-tier target voices only), explicit `weights` (`[]` = opt-out), and a `voices` sub-map restricted to the register's own secondaries (UI-control/UI-widget: font only, the ladders-only law). `faces` folded into `registers.functional.voices["Sub-title"].font`. The pass-through shape (`type.fonts`/`type.voices`) is unchanged and remains the escape hatch for a real exported doc config (BZZR, Modal jazz). |
| Forces | The intended-use canon (`docs/reference/typography/intended-use.md`, 2026-07-30) Layer 3 defines registers mapped onto the 15 voices, the 5-slot shape had no `styleName` path (named cuts were brands-pass-through-only), `faces` voices got a family but no character, 10 of 15 voices were unreachable from a spec, the preset revision program (ratified 2026-07-30) needs each palette's type re-reasoned from its story via the register-mapping method |
| Rejected | none named |
| Consequences | The migration (`scripts/migrate-type-registers.mjs`, 339 palettes) was proven byte-identical on the generated presets, with all rendered change deferred to the per-category revision PRs; the mapper is `registersToTypeConfig`; the categories gate gained a `schema` group (retired shapes, ownership, styleName tier, units) and generation throws on a retired shape. The quick map notes `scripts/migrate-type-registers.mjs` is kept deliberately as the executable record of the slots→registers rename. Issue #405. |
