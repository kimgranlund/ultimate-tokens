# SITE-mcp-hosting · Hosted Brand-Kit MCP — Spec & Plan (Cloudflare, account-based) · 2026-07-12 · draft / design
| Field | Value |
|---|---|
| Decision | One hosted MCP endpoint; a user authenticates when adding it to their agent (OAuth) and the server serves their account's brand kits. Identity is an Ultimate Tokens account via email magic-link, linked to the Lemon Squeezy subscription by email. Architecture: Cloudflare Pages for the static SPA, a Worker with `workers-oauth-provider` + `McpAgent` (Durable Objects) for MCP + OAuth, Streamable HTTP JSON-RPC 2.0 transport, Workers KV for kit blobs (`kit:<kitId>`), D1 for users/sessions/accounts/members/kits/ls_subscriptions, Resend for email, entitlement from LS webhook stored status (fail-open on LS downtime), a personal access token as the non-OAuth fallback. Phase A extracts a pure `mcp/brand-kit-core.mjs` shared by the stdio and hosted servers, parity-gated by a test; the hosted server adds only `list_kits` + a `kit` arg. §6a: `kit_id` is the client-minted `DocEnvelope.id` from `storage-and-sync-spec.md`, not server-minted; first push binds the id to its first-seen owner and a later push under a different account is rejected `404`; incoming ids must be UUID-shaped; identity is the id, never the name; conflicts resolve per SPEC-R15/R16. Gated by the `hostedMcp` Pro flag, which stays unwired in `TIER_FLAGS` until Phase E. |
| Forces | The product owns no domain (`<APP_DOMAIN>`/`<MCP_DOMAIN>` are placeholders and step zero of Phase B), the generator stays client-side (amended narrowly by ADR-021 for describe-palette only), no `fetch` in the app bundle (auth/sync go through web-only seams in `src/main.ts`), the Figma plugin stays offline (`networkAccess:"none"`), entitlement verified server-side never client-side, near-zero fixed cost free-tier-first, identical token surface to the downloadable server, Studio multi-seat needs accounts as the substrate |
| Rejected | The first draft's "publish a per-kit URL + bearer token (snapshot)" model, replaced by "one endpoint + OAuth + account↔kit (live, synced)" |
| Consequences | Introduces accounts and server-side kit sync as new scope; phased plan A (core + parity, repo only, `npm test`) → B (accounts + email) → C (kit sync) → D (authed MCP) → E (app integration, un-block `hostedMcp`, LS webhook) → F (Studio + hardening). Phase A starts now with no Cloudflare account. Conflict/versioning governed by `storage-and-sync-spec.md` SPEC-R15/R16, superseding this spec's earlier "out of scope for v1" note. Local set ids (`newSet` 7-char random slice, `"set-" + Date.now().toString(36)`) need a one-time pre-sync re-mint to real UUIDs. Open decisions §13: email provider (Resend recommended), `McpAgent`/DO vs hand-rolled, multi-kit UX (`list_kits` + `kit` arg recommended), email↔license mismatch (license-key link fallback recommended), Studio teams deferred to Phase F (recommended). Risks §14: OAuth client coverage, accounts as new surface area, parity drift, revocation latency, offline-Figma invariant. Tickets named: TKT-0029 (§6a), #377 (via ADR-021). |
