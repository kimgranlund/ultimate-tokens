# ramp@2 extremes and Match peer lightness: the before and after board (2026-10-09)

Evidence for T-0040 (ADR-037). `ramp@2` puts the lightest and darkest stops of every palette (050 to
100 and 900 to 950) on one shared lightness ladder with one tint, in every tone mode, and the opt-in
Match peer lightness mode puts every stop on that ladder. Stored kits keep rendering with `ramp@1`
until upgraded. Everything below is measured on the lane `plan/match-peer-lightness`.

Where to see it in the editor: open any kit, Color section. The ramp rows' first and last swatches
(050 to 100 and 900 to 950, "All" shows 075 and 925) now line up across palettes; the Radix view's steps
1 and 12 read them. Deselect every palette for the Global inspector: the "Match peer lightness" row sits
under Hue space and On-colors (Off by default); a kit still on `ramp@1` shows "Upgrade to latest" there.

## Command

- Base: `453ad603` (`git merge-base HEAD main`, the tree before T-0040). Commits: `2fbb40d1` (freeze
  `ramp@1`), `19c6f8a4` (the band rule's invariants), `1180a2f9` (memos), `13b96e52` (re-pins),
  `3bc5b924` (mode-isolation fixture), `12f1551a` (a citation), `a39a472c` (Match peer lightness), then
  the docs commit that adds this board.
- `node scripts/report-preset-fidelity.mjs --identity-control --migrate --authored --base 453ad603` (412 s)
- `node scripts/report-compute-neutral.mjs --base 453ad603` and the same with `--pin ramp=1` (52 s each)
- `node test/engine/peer-lightness.mjs` (SAMPLED), `npm test` through `gate_lock.py` (61 of 61 files),
  `npm run smoke` (build included)
- The tables below: `projectView(defaultDocument())` with `layers.ramp` 1 and 2, every tone mode.
- Not run locally, by the brief: the 8 full-corpus sweeps (`gate:sweeps`, CI runs them). The FULL
  allow-lists below were measured by focused probes that replay each gate's own predicate over the
  whole corpus; Gate A (the chroma envelope) was run on two corpus subsets (1 in 8 and 1 in 5), green.

## Follow-ups

- Stored kits stay `ramp@1` until a user presses "Upgrade to latest"; nothing re-pins them silently.
- The shadcn and Radix baselines and the Adia exports stay `ramp@1`-pinned, so no gate pins the
  default kit's `ramp@2` shadcn or Radix export yet.
- The compression cost is a decision for the owner: a distinctness pass (separate repeated pixels by
  a code where L* allows), or a wider anchored pivot room (clamps more anchors, against ADR-026), or
  leave it declared.
- `scripts/gen-categories.mjs` still counts and prints the `ramp@1` window `[9.95, 95.05]` in its
  summary line; `pivotWindow` is the `ramp@2` one.
- The FULL sweeps (`gate:sweeps`) were not run locally; CI runs them.
