# Two small fixes: the smoke script owns its Chrome (#717), and `model.mjs` keeps one hex-to-OKLCH conversion (#731)

Two unrelated defects, both small, grouped because each is too small to carry a plan of its own and neither touches the other's files. #717 is buildable today. #731 exists only on `plan/preset-intent-fidelity` (#681), so its unit waits for that plan to land and starts by a command, not by a date.

What the measurement found that the tickets did not say. It changes the criteria, so it comes first.

1. A normal `npm run smoke` run does not leak. The `finally` block's `SIGKILL` reaches the browser process, and its helper processes exit on their own within 2 s (3 alive at t+0, 0 at t+2 s, measured twice). The leak is the signal path: a run stopped with `SIGTERM` at 5 s exits 143 and leaves 9 Chrome processes, the listener holding port 9333. So the criterion is "no Chrome after a signalled run", with a 5 s grace for helpers, and a plain "no Chrome after a green run" would pass today and prove nothing.
2. The fixed port does more than orphan: it attaches to strangers. With a decoy HTTP server on 9333, `node test/smoke/smoke.mjs` sent the decoy 113 requests, waited the full 45 s deadline and failed with `smoke threw: Chrome CDP did not come up within 45s (last: HTTP 404)`, while the Chrome it had spawned sat unused. With a stale smoke Chrome on the port instead of a decoy, the run drives that browser and passes, which is what #717 reports for the `20298cc` figures.
3. Chrome Canary on this host (`Google Chrome 156.0.8068.0 canary`, at the path `smoke.mjs` already lists; `CHROME_BIN` is unset) writes `DevToolsActivePort` under `--remote-debugging-port=0` with a real temp `--user-data-dir`: two lines, the port then the browser websocket path, present after about 8.5 s, and `/json/version` answers on that port. That is the mechanism the fix rests on, and it is now verified on the one local Chrome and on CI's `google-chrome` by the first CI run of the plan branch.
4. `rgbToOklchLocal` (#731) duplicates a function of the same file. `src/ui/model.mjs:820` on 505416d7 exports `rgbToOklchArr`, the same Ottosson matrices, and `hexToOklch` at :836 wraps it. ## The design, stated once

### U1, the smoke launcher

One launcher, `test/smoke/chrome.mjs`, exporting two functions and nothing else:

- `launchChrome(bin, extraArgs, { deadlineMs })`. Makes a profile directory with `mkdtempSync(join(tmpdir(), "ultimate-tokens-smoke-"))`, spawns `bin` with `[...extraArgs, "--headless=new", "--no-sandbox", "--disable-gpu", "--disable-dev-shm-usage", "--remote-debugging-port=0", "--hide-scrollbars", "--window-size=1440,900", "--user-data-dir=<dir>", "about:blank"]` (the flags `smoke.mjs` passes today, the port at `0`), polls `<dir>/DevToolsActivePort` every 400 ms until its first line parses as a port or `deadlineMs` passes, and resolves `{ proc, port, dir, close }`. On the deadline it calls `close()` and rejects with the message `Chrome CDP did not come up within <s>s (last: <reason>)`, the shape the script prints today, so the CI diagnosis path is unchanged. `close()` is idempotent: `proc.kill("SIGKILL")`, then `rmSync(dir, { recursive: true, force: true })`; a second call is a no-op.
- `onExit(fn)`. Registers `fn` on `process.on("exit")` and on `SIGINT`, `SIGTERM` and `SIGHUP`; a signal handler runs `fn()` then `process.exit(128 + signal number)` (130, 143, 129), which is the exit code the shell would have reported for an unhandled signal, so a CI `timeout` or a `kill` reads the same.

`smoke.mjs` calls `onExit` before `launchChrome`, so a signal that lands during the 45 s start-up wait is also cleaned up; its `finally` calls `close()`; the `cdp()` helper reads `port` from the launch result; the `PORT` constant and the `spawn` are deleted. The `/json/version` and `/json/new` flow stays as it is: the discovered port replaces the fixed one, nothing else about the drive changes.

The `user-data-dir` prefix is the process needle: `pgrep -f 'user-data-dir=.*ultimate-tokens-smoke-'` matches every Chrome this script ever started and nothing else, on macOS and on the CI runner. Today's needle (`remote-debugging-port=9333`) stops matching once the fix lands, so the criteria below use the new one and, for the "today" column, the old one.

The unit test, `test/smoke/launcher.mjs`, runs without Chrome and without a build. `test/smoke/fixtures/fake-chrome.mjs` stands in for the browser: started as `process.execPath` with the fixture path as `extraArgs`, it reads `--user-data-dir=` and `--remote-debugging-port=` from its argv, exits 2 if the port flag is anything but `0` (so a launcher that regresses to a fixed port reds leg (a) instead of passing by accident), listens on `127.0.0.1:0`, answers `/json/version` with `{"Browser":"fake-chrome/1"}`, writes `DevToolsActivePort` (port, newline, `/devtools/browser/fake`) into the profile directory, and stays alive on a timer until killed. With `FAKE_CHROME_MUTE=1` it never writes the file. Legs, each printed as one `pass`/`FAIL` line, and the file exits 1 on any FAIL:

| leg | asserts |
|---|---|
| (a) discovery | `launchChrome(process.execPath, [fixture])` resolves; `port` equals line 1 of `<dir>/DevToolsActivePort`; `fetch("http://127.0.0.1:<port>/json/version")` returns the fake's JSON |
| (b) close | after `close()`, `process.kill(proc.pid, 0)` throws `ESRCH` within 2 s and `existsSync(dir)` is false; a second `close()` does not throw |
| (c) SIGTERM | a child `node test/smoke/launcher.mjs --child` installs `onExit`, launches the fake, prints `<fake pid> <dir>` and waits. The parent sends `SIGTERM`: child exit code 143, fake pid gone within 2 s, `dir` gone |
| (d) SIGINT | as (c) with `SIGINT`: exit 130 |
| (e) deadline | `FAKE_CHROME_MUTE=1` and `deadlineMs: 1500`: the launch rejects with a message starting `Chrome CDP did not come up within`, the fake pid is gone within 2 s, `dir` gone |

The test is not registered in `test/run.mjs`. It runs from the `smoke` script, `npm run build && node test/smoke/launcher.mjs && node test/smoke/smoke.mjs`, so CI's smoke step and every local `npm run smoke` run it, and it can be run alone on any host by `node test/smoke/launcher.mjs`. Registering it in `TESTS` instead would raise N and, under the post-#691 landing rule (`.sdlc/checks/baseline-agrees-check.sh`, `tests:` row), oblige a three-run baseline rerun on a quiet host for a 1 s test; that is Q1 for the owner, default no.
