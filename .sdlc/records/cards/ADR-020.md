# ADR-020 · `bundle.mjs` stays the single-file inliner; vite is not byte-comparable and not adopted · 2026-07-17 · DECIDED (ratified 2026-07-17; TKT-0028, a spike, no follow-up work implied)
| Field | Value |
|---|---|
| Decision | Keep `bundle.mjs`. Do not adopt vite for the Figma-sandbox-embeddable single-file artifact. Instead, harden `bundle.mjs` with a `preflight()` whole-graph scan that runs before any transform. |
| Forces | TKT-0028's acceptance bar was "adopt only on byte-comparable output", vite/rolldown output carries its own module-runtime prelude and a different code shape so byte-identical output is categorically unreachable, the vite build's JS+CSS alone was ~3397.9 KB vs `bundle.mjs`'s 2832.8 KB (~20% larger) and minifying barely helps because most bytes are inert data in string literals (curated palettes, base64 fonts, embedded binder and MCP source), the documented `export default` limitation is triggered by zero current files (a latent risk, not an active one) |
| Rejected | vite single-file build (lib mode, `inlineDynamicImports: true`, `cssCodeSplit: false`) as the replacement bundler |
| Consequences | `MODS`/`KEY` registries stay hand-maintained; every new module in the import graph still needs an entry in both (`adding-export-formats`/`building-editor-sections` unaffected). `preflight()` reports every registry problem in one itemized error: (a) a `KEY` entry pointing at a missing `MODS` key, (b) two `MODS` entries sharing a basename in different directories, (c) the per-import/`export default` check now run across the whole graph with source-file context. Verified `npm test` and `npm run build` green with byte-identical `dist/ultimate-tokens.html` (2832.8 KB) and `figma/plugin/ui.html` (2835.8 KB) before/after; `npm run smoke` green end to end including the Apply-to-Figma consent gate. If a future change needs a default export, or vite gains a prelude-free concatenation mode at comparable size, this ADR is the record to revisit. |
